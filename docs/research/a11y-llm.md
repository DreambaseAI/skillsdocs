# PART 1 — Accessibility

## 1.1 Document structure: how a "book" should be marked up

### The route model this assumes

```
/                              home / directory
/<owner>/<repo>                the book: cover + table of contents
/<owner>/<repo>/<skill>        a chapter (one skill)
```

### Landmark skeleton (one per reader page)

```tsx
// src/app/[owner]/[repo]/[skill]/page.tsx  (abridged)
<>
  <SkipLinks />                                  {/* see 1.3 */}

  <header role="banner" className="…">
    {/* book brand, owner/repo, global actions */}
  </header>

  <nav id="toc" aria-label="Table of contents" role="doc-toc" className="…">
    <ol>{/* chapters */}</ol>
  </nav>

  <main id="main">
    <article
      id="book"
      aria-labelledby="book-title"
      // DPUB role for the whole work
      role="doc-part"
    >
      {/* Visually hidden if the cover already shows it; still the page's only h1 */}
      <h1 id="book-title">
        <span className="sr-only">{repo} — </span>
        {chapter.title}
      </h1>

      <section
        role="doc-chapter"
        aria-labelledby="chapter-title"
        tabIndex={-1}          // focus target on chapter change (1.5)
        ref={chapterRef}
      >
        <h2 id="chapter-title">{chapter.title}</h2>
        <SkillMarkdown html={chapter.html} />   {/* headings already shifted, see 1.2 */}
      </section>
    </article>
  </main>

  <nav aria-label="Page navigation">{/* prev / next page buttons */}</nav>

  <footer role="contentinfo">…</footer>

  {/* live regions, always present in the DOM, never conditionally mounted */}
  <div id="page-status" role="status" aria-live="polite" aria-atomic="true" className="sr-only" />
  <div id="alerts"      role="alert"  aria-live="assertive" aria-atomic="true" className="sr-only" />
</>
```

**Rules:**

- Exactly **one `<main>`**, exactly **one `<h1>`** per rendered document. WCAG 1.3.1, 2.4.6.
- Every repeated landmark of the same type gets a distinguishing `aria-label` (`<nav aria-label="Table of contents">` vs `<nav aria-label="Page navigation">`). Never `aria-label="navigation"` — screen readers already announce the role.
- Use **DPUB-ARIA** roles where they add meaning and are well supported: `doc-toc`, `doc-chapter`, `doc-cover`, `doc-pagebreak`, `doc-abstract`, `doc-credits`, `doc-bibliography`, `doc-endnotes`. Support is uneven across NVDA/JAWS/VoiceOver — **[inferred]** treat them as additive only. Never rely on a DPUB role for something a native element or `aria-label` could carry.
- **Virtual page breaks**: if the reader paginates continuous prose, emit a real page-break marker at each boundary so screen-reader and braille users can navigate and cite by page:

```html
<span role="doc-pagebreak" aria-label="Page 12" id="page-12"></span>
```

This is the EPUB-standard pattern and is the only reliable way to expose "page 12 of 48" to AT in a scrolling reader. Also emit `<link rel="alternate">`-style page-list navigation in the TOC drawer.

### The pagination trap

If pagination is done by `overflow: hidden` + CSS columns + transform (the classic "book" effect), **off-screen columns remain in the accessibility tree and in the tab order**. Two mitigations, both required:

1. Only the current spread's container is visible; others get `inert` (native attribute, supported in all evergreen browsers) — `inert` removes from tab order *and* the a11y tree in one shot. React 19 supports `inert` as a plain boolean prop.
2. Offer a **"Continuous scroll"** reading mode in the controls panel and make it the default when `prefers-reduced-motion: reduce` is set or when the viewport is under 640 CSS px. Paginated reading is a presentation choice; a scrolling document is always the accessible fallback (WCAG 1.4.10 Reflow effectively demands it at 400% zoom).

## 1.2 Heading hierarchy for arbitrary third-party markdown — **resolved**

**The problem.** A `SKILL.md` typically opens with `# Skill Name`, then uses `##`/`###`. Our chapter page also needs an `<h1>` for the chapter/book. Rendering both produces two `<h1>`s, and if the skill author skipped a level (`#` → `###`) the outline breaks.

**The decision (do all four, in this order, in the rehype pipeline):**

1. **Strip a leading duplicate H1.** If the *first* node of the markdown body is an `h1` whose normalized text equals the SKILL.md frontmatter `name` or `title`, drop it. (Normalize: lowercase, collapse whitespace, strip punctuation.) This is the common case and it costs nothing.
2. **Shift everything down by one level** with `rehype-shift-heading` (MIT, v2.0.0 — **[verified]** `npm view`), `{ shift: 1 }`. The skill's `h1` → `h2`, `h2` → `h3`, … `h5` → `h6`.
3. **Handle `h6` overflow.** After a +1 shift, a source `h6` would become `h7`, which does not exist. `rehype-shift-heading` clamps to `h6`. Clamping silently flattens deeply-nested docs; that is acceptable and is what every docs platform does. If you want to be exact, render the overflow as `<div role="heading" aria-level="7">` — **[inferred]** not worth it; clamp.
4. **Repair skipped levels.** Walk the shifted heading list and, for any heading whose level jumps by more than 1 from the previous heading, clamp it to `previousLevel + 1`. Preserve the original level in `data-source-level` for debugging. This makes the outline valid regardless of what the repo author wrote, which matters because we render *arbitrary third-party content* and cannot fix it upstream.

Result: our chapter page outline is always `h1` (book/chapter title we control) → `h2` (chapter heading) → `h3+` (skill's own structure), with no gaps and no second `h1`.

### The pipeline (all MIT — **[verified]**)

```bash
pnpm add unified remark-parse remark-gfm remark-rehype rehype-raw rehype-sanitize \
         rehype-shift-heading rehype-slug rehype-autolink-headings rehype-stringify shiki
```

```ts
// src/lib/markdown.ts
import { unified } from 'unified'
import remarkParse from 'remark-parse'
import remarkGfm from 'remark-gfm'
import remarkRehype from 'remark-rehype'
import rehypeRaw from 'rehype-raw'
import rehypeSanitize, { defaultSchema } from 'rehype-sanitize'
import rehypeShiftHeading from 'rehype-shift-heading'
import rehypeSlug from 'rehype-slug'
import rehypeAutolinkHeadings from 'rehype-autolink-headings'
import rehypeStringify from 'rehype-stringify'
import { visit } from 'unist-util-visit'

/** 4) repair skipped heading levels, in-place, after the shift */
function rehypeRepairOutline() {
  return (tree: any) => {
    let prev = 2 // our chapter <h2> is the parent context
    visit(tree, 'element', (node: any) => {
      const m = /^h([1-6])$/.exec(node.tagName)
      if (!m) return
      const level = Number(m[1])
      const fixed = level > prev + 1 ? prev + 1 : level
      if (fixed !== level) {
        node.properties = { ...node.properties, 'data-source-level': level }
        node.tagName = `h${fixed}`
      }
      prev = fixed
    })
  }
}

const schema = {
  ...defaultSchema,
  attributes: {
    ...defaultSchema.attributes,
    '*': [...(defaultSchema.attributes?.['*'] ?? []), 'className', 'id', 'dataSourceLevel'],
    img: [...(defaultSchema.attributes?.img ?? []), 'loading', 'decoding'],
    code: [...(defaultSchema.attributes?.code ?? []), 'className'],
  },
}

export const skillMarkdown = unified()
  .use(remarkParse)
  .use(remarkGfm)
  .use(remarkRehype, { allowDangerousHtml: true })
  .use(rehypeRaw)
  .use(rehypeSanitize, schema)      // MUST run before we trust anything: this is third-party content
  .use(rehypeShiftHeading, { shift: 1 })
  .use(rehypeRepairOutline)
  .use(rehypeSlug)
  .use(rehypeAutolinkHeadings, {
    behavior: 'append',
    properties: { className: 'heading-anchor', ariaHidden: false },
    content: { type: 'element', tagName: 'span', properties: { className: 'sr-only' }, children: [] },
  })
  .use(rehypeStringify)
```

**Autolink headings a11y note:** the common `aria-hidden="true" tabindex="-1"` anchor pattern hides the link from AT entirely, which is fine, *but* many implementations leave it focusable. Either fully hide it (`aria-hidden` + `tabIndex={-1}`) or give it a real accessible name (`Permalink to "Writing effective descriptions"`). Do **not** ship a focusable, unnamed `#` link — that's a 2.4.4 / 4.1.2 failure. **[inferred]** Prefer the named-visible-on-focus variant; it also satisfies 2.4.7.

**Sanitization is an accessibility requirement, not just security.** Third-party markdown can contain `tabindex="5"`, `aria-hidden="true"` on interactive content, `role="presentation"` on tables, and autoplay media. The schema above strips all of that by default. Explicitly deny: `tabindex` on anything, `aria-hidden`, `autoplay`, `accesskey`, `style`.

## 1.3 Skip links

Long-form reading with a persistent header, TOC rail, and controls bar means a keyboard user hits many controls before content. Ship **three** skip links in a single visually-hidden-until-focused list, first in the DOM:

```tsx
// src/components/skip-links.tsx
export function SkipLinks() {
  return (
    <div className="skip-links">
      <a href="#main">Skip to the chapter</a>
      <a href="#toc">Skip to the table of contents</a>
      <a href="#reader-controls">Skip to reading controls</a>
    </div>
  )
}
```

```css
/* globals.css */
.skip-links a {
  position: absolute;
  left: 0.5rem;
  top: -100vh;
  z-index: 9999;
  padding: 0.625rem 1rem;                /* ≥24×24 CSS px target: 2.5.8 */
  border-radius: var(--radius-md);
  background: var(--color-background);
  color: var(--color-foreground);
  box-shadow: 0 0 0 2px var(--color-ring), 0 8px 24px rgb(0 0 0 / 0.2);
  font: inherit;
}
.skip-links a:focus-visible { top: 0.5rem; }
@media (forced-colors: active) {
  .skip-links a { background: Canvas; color: CanvasText; border: 2px solid CanvasText; }
}
```

Targets must be real elements with `tabIndex={-1}` (`<main id="main" tabIndex={-1}>`), otherwise Safari and Firefox move the scroll position but not the focus ring. WCAG 2.4.1.

**2.4.11 Focus Not Obscured (Minimum, AA):** the skip link, and every focusable element, must not be fully hidden behind the sticky header or the bottom controls bar. Add:

```css
:root { --reader-header-h: 3.5rem; --reader-footer-h: 4rem; }
#main :is(a, button, [tabindex]) { scroll-margin-top: calc(var(--reader-header-h) + 1rem);
                                   scroll-margin-bottom: calc(var(--reader-footer-h) + 1rem); }
```

`scroll-margin` is the standard fix; `scroll-padding-top` on the scroll container also works. Verify manually by tabbing through with the header pinned.

## 1.4 Keyboard navigation model

See **Part 2** for the full shortcut map. Structural rules:

- **Every shortcut has a visible control.** Nothing is keyboard-only. (2.1.1 + 3.2.4)
- **Roving tabindex, not 20 tab stops.** The chapter list in the TOC and the page-thumbnail strip are composite widgets: one tab stop, arrow keys within, `Home`/`End` to jump. Use Base UI `NavigationMenu` / `Toolbar` primitives — they implement roving tabindex per APG. **[verified]** Base UI accessibility doc: "Many components provide support for arrow keys, alphanumeric keys, Home, End, Enter, and Esc."
- **Tab order matches visual order.** With CSS-column pagination that is easy to violate; test with `Tab` at 320px and at 1600px.
- **No keyboard trap** other than the intentional modal one (2.1.2). Any embedded iframe (video demos in a skill's README) needs a documented escape.
- **`Esc` always closes the topmost overlay** and returns focus to the trigger. Base UI does this for Dialog/Drawer/Popover/Menu.

## 1.5 Focus management and focus rings

### Visible focus — this is on us, not Base UI

Base UI's own docs state it explicitly: *"While Base UI components manage focus, it's the developer's responsibility to visually indicate focus."* **[verified]** `@base-ui/react/docs/react/overview/accessibility.md`.

Ship a single global focus token and never `outline: none` without a replacement:

```css
@layer base {
  :root {
    --focus-ring-width: 2px;
    --focus-ring-offset: 2px;
    --focus-ring-color: var(--ring);
  }
  :focus-visible {
    outline: var(--focus-ring-width) solid var(--focus-ring-color);
    outline-offset: var(--focus-ring-offset);
    border-radius: inherit;
  }
  /* keep a ring in Windows HCM where custom colors are dropped */
  @media (forced-colors: active) {
    :focus-visible { outline: 3px solid Highlight; outline-offset: 2px; }
  }
}
```

**Targets:**
- **2.4.7 Focus Visible (AA):** any visible indicator.
- **2.4.13 Focus Appearance (AAA) — achievable, do it:** the indicator must be at least a 2 CSS px thick perimeter of the component (or equivalent area) and have ≥3:1 contrast between focused and unfocused states. The 2px solid outline with 2px offset above satisfies this on both stone-light and stone-dark surfaces provided `--ring` is chosen against both. Verify `--ring` vs `--background` and vs `--card` at ≥3:1.
- **2.4.12 Focus Not Obscured (Enhanced, AAA):** *no part* of the focused component may be hidden. With a sticky header this requires the `scroll-margin` fix above plus never using a floating bottom bar that overlaps content — use `padding-bottom` on the scroll container equal to the bar height instead of letting it float over text.

### Focus movement policy for a reader

| Event | Focus behavior | Announcement |
|---|---|---|
| Page turn *within* a chapter | **Do not move focus.** Keep it on the page-turn button. | `role="status"` polite: "Page 12 of 48" |
| Chapter change (next/prev/TOC click) | Move focus to the chapter `<section tabIndex={-1}>`; `scrollIntoView({ block: 'start', behavior: reduced ? 'auto' : 'smooth' })` | polite: "Chapter 3 of 9: Writing skills. Page 1 of 6." |
| Client-side route change (Next App Router) | Next does **not** reliably move focus on soft navigation — move it yourself to `<h1>` or `<main>` with `tabIndex={-1}` in a `useEffect` keyed on `usePathname()` | polite: page `<title>` |
| Opening controls drawer | Base UI handles it (`initialFocus`) | — |
| Closing controls drawer | Base UI restores to trigger (`finalFocus`) | — |
| Search results update | Focus stays in the input | polite: "7 results" (debounced 500ms) |
| Copy install command | Focus stays on button | polite: "Copied `npx skills add anthropics/skills` to clipboard" |

Never `autoFocus` on page load — it steals context from AT users and violates 3.2.1 expectations in practice.

## 1.6 Focus trapping in the controls sheet / dialog — what Base UI gives us

**Base UI handles (do not reimplement):**

| Concern | Base UI |
|---|---|
| `role="dialog"` / `aria-modal` | ✅ Dialog, AlertDialog, Drawer |
| `aria-labelledby` / `aria-describedby` wiring | ✅ via `Dialog.Title` / `Dialog.Description` — **you must render them** |
| Focus trap | ✅ `modal={true}` or `modal="trap-focus"` — **[verified]** `DialogRoot.d.ts:36` |
| Scroll lock | ✅ with `modal={true}` (`'trap-focus'` traps focus but **does not** lock scroll) |
| Outside pointer inertness | ✅ with `modal={true}`; disable dismissal with `disablePointerDismissal` |
| Initial focus target | ✅ `Dialog.Popup initialFocus={ref | (openType) => …}` |
| Return focus on close | ✅ `Dialog.Popup finalFocus` |
| `Esc` to close | ✅ |
| Nested dialogs | ✅ `data-nested`, `data-nested-dialog-open` |
| Roving tabindex in Menu/Select/Tabs/Toolbar | ✅ per WAI-ARIA APG |
| Swipe-to-dismiss drawer with keyboard equivalents | ✅ `Drawer` (Base UI 1.7) |

**We must add:**

1. **Always render `Dialog.Title`.** If the design has no visible title, render it in `.sr-only`. A dialog without an accessible name is a 4.1.2 failure and is the single most common Base UI/Radix mistake.
2. **Always render a `Dialog.Close` *inside* `Dialog.Popup`** when `modal` is `true` or `'trap-focus'`. Base UI's own type docs say this verbatim: *"render `<Dialog.Close>` inside `<Dialog.Popup>` so touch screen readers can escape the popup."* **[verified]** `DialogRoot.d.ts:32-34`. Touch-screen-reader users have no `Esc`.
3. **Visible focus ring** inside the popup (§1.5).
4. **Reduced motion** on the `data-starting-style` / `data-ending-style` transitions (§1.8).
5. **Forced-colors background** on the translucent popup (§1.10) — `backdrop-filter` is dropped in HCM and a translucent panel becomes unreadable.
6. **Announce state that isn't focus-visible**, e.g. "Serif font applied", via the polite live region.
7. **Non-modal choice:** the desktop reading-controls panel should be `modal="trap-focus"` **or** non-modal (`modal={false}`) so users can see the text reflow live while adjusting. **[inferred] Recommendation:** desktop = `modal={false}` popover anchored to the controls button (users need to see the effect of font-size changes on the text behind it); mobile = `Drawer` with `modal={true}`. Document this divergence.

```tsx
// src/components/reader/controls-panel.tsx (desktop, non-modal)
<Popover.Root>
  <Popover.Trigger
    id="reader-controls"
    aria-label="Reading controls"
    aria-keyshortcuts="Comma"
    className="size-11 …"          /* 44×44 – exceeds 2.5.8, meets 2.5.5 AAA */
  >
    <HugeiconsIcon icon={Settings02Icon} aria-hidden />
  </Popover.Trigger>
  <Popover.Portal>
    <Popover.Positioner sideOffset={8}>
      <Popover.Popup className="…" aria-label="Reading controls">
```

Use `aria-keyshortcuts` on every control that has a shortcut (`aria-keyshortcuts="Comma"`, `"Shift+Slash"`, `"BracketRight"`). It is the only standardized way to expose a shortcut to AT, and NVDA/JAWS read it.

## 1.7 Screen reader announcements for page changes

```tsx
// src/components/reader/reader-announcer.tsx
'use client'
import { useEffect, useRef, useState } from 'react'

export function useAnnounce(delay = 300) {
  const [message, setMessage] = useState('')
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null)
  const announce = (text: string) => {
    if (timer.current) clearTimeout(timer.current)
    // clear first so identical consecutive messages re-announce
    setMessage('')
    timer.current = setTimeout(() => setMessage(text), delay)
  }
  useEffect(() => () => { if (timer.current) clearTimeout(timer.current) }, [])
  return { message, announce }
}
```

```tsx
<div role="status" aria-live="polite" aria-atomic="true" className="sr-only">
  {message}
</div>
```

**Non-negotiable details:**

- The live region container must be **in the DOM on first render**, empty. Mounting a node that already has text does not announce in most SR/browser combos.
- **Debounce 250–400ms.** Holding `→` to flip 30 pages must produce one announcement ("Page 42 of 48"), not 30. The clear-then-set two-tick pattern above is required for repeat announcements of the same string.
- **`polite`, never `assertive`, for page turns.** Reserve `role="alert"` for errors (fetch failure, rate limit).
- **Announce the semantic unit, not the mechanic.** "Page 12 of 48, Chapter 3: Writing skills" beats "Page changed".
- **Update `document.title` too** on chapter change — `Writing skills · anthropics/skills · Skills Book`. Some SR users navigate by window title, and it's what browser history shows.
- **`aria-atomic="true"`** so the whole sentence is re-read, not just the changed number.
- Add `aria-current="page"` on the active TOC item and `aria-current="true"` on the active page dot.

Also expose page position non-live for on-demand reading:

```html
<p class="sr-only" id="reading-position">Page 12 of 48 in chapter 3 of 9.</p>
<section role="doc-chapter" aria-describedby="reading-position" …>
```

## 1.8 Reduced motion

A page-turn animation is exactly the class of motion that triggers vestibular disorders (large-area translate/rotate/3D).

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Plus **behavioral**, not just cosmetic, changes:

- Page turns become **instant cross-fades or instant swaps**, not 3D flips or slides.
- `scrollIntoView({ behavior: prefersReducedMotion ? 'auto' : 'smooth' })` — the CSS override above does not affect the JS option.
- The Drawer's swipe animation: Base UI drives it via `data-starting-style` / `data-ending-style` and CSS custom properties like `--drawer-swipe-progress` — **[verified]** `docs/react/components/drawer.md`. Gate the `transition-*` utilities behind `motion-safe:` (Tailwind 4.3.3 has this variant — **[verified]**): `motion-safe:transition-transform motion-safe:duration-[450ms]`.
- Provide an explicit **"Reduce motion"** switch in the controls panel that ORs with the media query and persists — some users can't set the OS preference (shared/kiosk machines) and some want it only here.

```ts
// src/lib/use-reduced-motion.ts
'use client'
import { useSyncExternalStore } from 'react'
const q = () => window.matchMedia('(prefers-reduced-motion: reduce)')
export function useSystemReducedMotion() {
  return useSyncExternalStore(
    (cb) => { const m = q(); m.addEventListener('change', cb); return () => m.removeEventListener('change', cb) },
    () => q().matches,
    () => false, // SSR
  )
}
```

Set `data-reduced-motion="true"` on `<html>` from the user setting and add `@custom-variant reduce-motion (&:is([data-reduced-motion="true"] *));` in `globals.css` next to the existing `@custom-variant dark`.

## 1.9 Text spacing resilience (1.4.12 AA) and typographic AAA (1.4.8)

**1.4.12 Text Spacing (AA)** — **[verified]** verbatim from W3C: no loss of content or functionality when the user sets *line height ≥ 1.5×* font size, *paragraph spacing ≥ 2×*, *letter spacing ≥ 0.12×*, *word spacing ≥ 0.16×*.

For a reading app that *itself* offers spacing controls this is subtle: our own controls must not be the ceiling, and a user stylesheet/bookmarklet must not break the layout.

**Rules:**

- **Never fix the height of a text container.** No `h-10` on a button with a label, no `h-[60px]` on a card header. Use `min-h-*` + padding.
- **Never `overflow: hidden` on text containers.** Use `overflow: visible` or `overflow: auto`. Line clamping is allowed on *summaries* only, never on body prose.
- **No `white-space: nowrap`** on anything that can be a sentence.
- Buttons, badges, nav items: `inline-flex items-center min-h-11 px-3 py-2` — never `h-11`.
- Test with the **Text Spacing bookmarklet** (Steve Faulkner's) in CI as a manual gate, and with this snippet in a Playwright a11y test:

```ts
await page.addStyleTag({ content: `
  * { line-height: 1.5 !important;
      letter-spacing: 0.12em !important;
      word-spacing: 0.16em !important; }
  p, li, h1, h2, h3, h4, h5, h6 { margin-bottom: 2em !important; }
` })
// then assert no element has scrollWidth > clientWidth on the body axis
```

**1.4.8 Visual Presentation (AAA)** — **[verified]** verbatim, five requirements. This is *the* AAA criterion a reading app should target, and our controls panel is how we get it:

| 1.4.8 requirement | How the controls panel satisfies it |
|---|---|
| "Foreground and background colors can be selected by the user." | Theme picker with ≥4 presets (Paper / Sepia / Night / High-contrast) **plus** a custom fg/bg pair. Persist to `localStorage` and re-emit as CSS vars on `<html>`. |
| "Width is no more than 80 characters or glyphs (40 if CJK)." | Measure control with `--measure` in `ch`; default `68ch`, max `80ch`. Never let a wide viewport produce a 120-character line. |
| "Text is not justified." | Default `text-align: start`. If you offer justification as an option, it must be opt-in and never default, and pair it with `hyphens: auto`. |
| "Line spacing ≥ 1.5 within paragraphs; paragraph spacing ≥ 1.5× line spacing." | Line-height control, default `1.65`; paragraph spacing `2.5em`-ish derived from it. Do not ship a default below 1.5 for body prose. |
| "Text can be resized to 200% without horizontal scrolling." | Covered by §1.11. |

**1.4.4 Resize Text (AA):** never set root font size in `px`. `html { font-size: 100% }` and everything downstream in `rem`. Tailwind 4's default `rem` scale is fine; the danger is arbitrary values like `text-[14px]`. Ban them with a lint rule / code review note.

## 1.10 Contrast, prefers-contrast, forced-colors

### Contrast targets

| Content | AA (required) | AAA (target) |
|---|---|---|
| Body prose | 4.5:1 | **7:1** |
| Large text (≥24px, or ≥18.66px bold) | 3:1 | 4.5:1 |
| UI component boundaries, icons, focus ring, chart strokes | 3:1 (1.4.11) | — |
| Placeholder text | 4.5:1 (it *is* text) | 7:1 |
| Disabled controls | exempt, but keep ≥3:1 anyway | — |

Because Base UI's own doc recommends considering **APCA** (**[verified]**), and because the reading surface is the product: **[inferred] Recommendation** — gate the *default* Paper and Night themes on **APCA Lc ≥ 75 for body text** (roughly ≈7:1 WCAG 2 for typical mid-tones) and keep WCAG 2 ratios as the CI-enforced floor since that's what axe measures. Ship a `High contrast` theme preset at Lc ≥ 90.

Muted stone text (`--muted-foreground`) is the usual failure. Audit every `text-muted-foreground` usage on `--background`, `--card`, `--popover`, **and** on the translucent menu surface (which composites over arbitrary page content — measure against the *worst-case* backdrop, not the average).

### `prefers-contrast`

```css
@media (prefers-contrast: more) {
  :root {
    --muted-foreground: var(--foreground);
    --border: color-mix(in oklch, var(--foreground) 60%, transparent);
    --focus-ring-width: 3px;
  }
  /* kill translucency: composited text is the #1 contrast risk */
  .translucent-surface { backdrop-filter: none; background: var(--popover); }
}
```

Tailwind exposes this as `contrast-more:` (**[verified]** present in 4.3.3). Use `contrast-more:bg-popover contrast-more:backdrop-filter-none` on every translucent menu.

### `forced-colors` / Windows High Contrast Mode

In forced-colors mode the UA replaces `color`, `background-color`, `border-color`, `box-shadow` (dropped), `background-image` on non-`<img>` (dropped), and **`backdrop-filter` is ignored**. Our translucent menus will render with a *transparent* background over arbitrary content → unreadable. This is the highest-risk a11y bug in the current design direction.

```css
@media (forced-colors: active) {
  /* opt into the system palette explicitly */
  :root { forced-color-adjust: auto; }

  .translucent-surface,
  [data-slot="popover-popup"],
  [data-slot="dialog-popup"],
  [data-slot="drawer-popup"],
  [data-slot="menu-popup"] {
    background: Canvas;
    color: CanvasText;
    border: 1px solid CanvasText;
    backdrop-filter: none;
    box-shadow: none;
  }

  /* icon-only buttons lose their background; give them a visible boundary */
  button, [role="button"] { border: 1px solid ButtonBorder; }

  /* selected / current state must not rely on background alone */
  [aria-current="page"], [aria-selected="true"], [data-selected] {
    background: Highlight; color: HighlightText; forced-color-adjust: none;
  }

  /* decorative gradients / mesh backgrounds must vanish, not fight the palette */
  .decorative-gradient { display: none; }

  :focus-visible { outline: 3px solid Highlight; outline-offset: 2px; }
}
```

System color keywords to use: `Canvas`, `CanvasText`, `LinkText`, `VisitedText`, `ActiveText`, `ButtonFace`, `ButtonText`, `ButtonBorder`, `Field`, `FieldText`, `Highlight`, `HighlightText`, `GrayText`, `Mark`, `MarkText`, `AccentColor`, `AccentColorText`.

**Charts and SVG in HCM:** SVG `fill`/`stroke` are *not* forced. A multi-series chart collapses to invisible-or-identical. Fix: set `forced-color-adjust: none` on the chart root and swap to a `CanvasText`-based monochrome encoding with **pattern/dash differentiation** (see §1.14).

**Tailwind:** the `forced-colors:` variant exists in 4.3.3 (**[verified]**). Prefer the raw `@media (forced-colors: active)` block above for the global reset, and use `forced-colors:` utilities for one-offs.

## 1.11 Zoom, reflow, and orientation

- **1.4.10 Reflow (AA):** content must be usable at **320 CSS px wide** (= 1280px at 400% zoom) with no two-dimensional scrolling. Concretely: at a 1280×1024 viewport zoomed to 400%, the reader must be single-column, the TOC must collapse into the drawer, the controls bar must not require horizontal scroll, and **paginated mode must auto-fall back to continuous scroll** (a fixed-page book layout cannot reflow).
- Test matrix (add to Playwright): `320×256`, `320×512`, `375×667`, `768×1024`, `1280×1024 @ 400% (=320×256 CSS)`, `1920×1080`.
- **1.4.4 Resize text (AA):** 200% text-only zoom (Firefox "Zoom text only") must not clip. This is stricter than page zoom and catches fixed-height containers.
- **1.3.4 Orientation (AA):** never lock to portrait/landscape.
- Horizontal-scroll exceptions permitted by 1.4.10: code blocks, wide tables, diagrams. Each must be its own `overflow-x: auto` region with `tabIndex={0}` **and** an accessible name so keyboard users can scroll it:

```tsx
<div role="region" aria-label="Code sample, horizontally scrollable" tabIndex={0}
     className="overflow-x-auto focus-visible:outline-2 …">
  <pre>…</pre>
</div>
```

(Adding `tabIndex={0}` to a scrollable region is required — Chrome/Safari do not make overflow containers keyboard-scrollable without it, and axe flags `scrollable-region-focusable`.)

- **`meta viewport`:** `width=device-width, initial-scale=1` only. Never `maximum-scale` or `user-scalable=no` (1.4.4 failure). In Next 16 use `export const viewport: Viewport = { width: 'device-width', initialScale: 1 }` and do **not** add `maximumScale`.

## 1.13 Images we don't control, code blocks, copy buttons

### Alt text for third-party images

Skill READMEs contain screenshots, badges, and diagrams whose `alt` may be missing, empty, or garbage (`image.png`).

**Decision tree, implemented in the rehype pipeline:**

```ts
function rehypeSkillImages(opts: { rawBase: string }) {
  return (tree: any) => visit(tree, 'element', (node: any) => {
    if (node.tagName !== 'img') return
    const p = node.properties ?? {}
    const src = String(p.src ?? '')
    const alt = typeof p.alt === 'string' ? p.alt.trim() : undefined

    // 1. resolve relative paths against raw.githubusercontent.com
    if (src && !/^(https?:|data:)/.test(src)) p.src = new URL(src, opts.rawBase).toString()

    // 2. shields.io / badge URLs -> decorative-ish but usually meaningful; keep author alt,
    //    otherwise derive from the badge path (e.g. "badge/license-MIT-green")
    // 3. author gave alt="" -> RESPECT IT. Empty alt is a valid decorative signal.
    if (alt === '') { p.role = 'presentation'; return }

    // 4. alt missing entirely -> do NOT invent a description. Mark it.
    if (alt === undefined) {
      p.alt = ''
      p.role = 'presentation'
      p['data-alt-missing'] = 'true'
    }

    // 5. useless filename alt -> treat as missing
    if (alt && /^(image|img|screenshot|untitled)?[-_ ]?\d*\.(png|jpe?g|gif|webp|svg)$/i.test(alt)) {
      p.alt = ''
      p.role = 'presentation'
      p['data-alt-missing'] = 'true'
    }

    p.loading = 'lazy'; p.decoding = 'async'
    node.properties = p
  })
}
```

**Why `alt=""` rather than a guessed description:** WCAG 1.1.1 requires a *text alternative that serves the equivalent purpose*. A wrong description is worse than none — it actively misinforms. Silently marking the image decorative removes noise for SR users without lying. **[inferred]**

**Then surface it, don't hide it:**

- Render a small visible caption beneath any `data-alt-missing` image: *"Image without a description — [view original on GitHub](…)"* linking to the raw file. That gives SR users a route to the content and gently pressures repo authors.
- Show a per-book **"Accessibility report"** panel: *"3 of 11 images in this book are missing descriptions."* with a "Open an issue on the repo" deep link (`https://github.com/{owner}/{repo}/issues/new?title=…&body=…`). This turns a compliance problem into a product feature and is a genuine differentiator.
- **[inferred]** Optional, opt-in, clearly labeled: an LLM-generated description behind a disclosure — `<figcaption>AI-generated description (not authored by the repo maintainer): …</figcaption>`. Never inject it into `alt` where it is indistinguishable from author-written text.

**SVG:** third-party inline SVG must get `role="img"` + `aria-label`, or `aria-hidden="true"` if decorative. The sanitizer should strip inline `<svg>` entirely unless you have a good reason — it's also an XSS surface.

**HugeIcons:** `<HugeiconsIcon icon={X} aria-hidden />` inside a labeled button; `<HugeiconsIcon icon={X} role="img" aria-label="…" />` only when the icon is the sole content and there is no wrapping labeled control.

Shiki's dual-theme output (`--shiki-light`/`--shiki-dark` CSS vars) makes this manageable.

- Long lines: offer a "Wrap lines" toggle in the controls panel; wrapping is the reflow-friendly default at narrow widths.

### Copy buttons

```tsx
'use client'
export function CopyButton({ text, label }: { text: string; label: string }) {
  const [copied, setCopied] = useState(false)
  const { message, announce } = useAnnounce(0)

  async function copy() {
    try {
      await navigator.clipboard.writeText(text)
      setCopied(true); announce('Copied to clipboard')
      setTimeout(() => setCopied(false), 2000)
    } catch {
      announce('Copy failed. Select the text and press Control or Command C.')
    }
  }

  return (
    <>
      <button
        type="button"
        onClick={copy}
        aria-label={label}                    /* stable name; does NOT change to "Copied" */
        className="inline-flex size-11 items-center justify-center …"
      >
        <HugeiconsIcon icon={copied ? Tick02Icon : Copy01Icon} aria-hidden />
      </button>
      <span role="status" aria-live="polite" className="sr-only">{message}</span>
    </>
  )
}
```

**Why the label must not change:** swapping `aria-label` from "Copy" to "Copied" mid-interaction changes the element's accessible name while focus is on it — voice-control users ("click Copy") lose the target, and some SRs re-announce confusingly. Announce success in a *separate* live region and keep the name stable. This is the single most common copy-button a11y bug.

Also: the visible tooltip "Copied!" must not be the only feedback (1.4.13 requires hoverable/dismissable content anyway) — the live region covers non-visual users.

## 1.14 Accessible charts

Any chart (skill counts by category, activity sparkline, contributor graph):

1. **`role="img"` + `aria-label`** with the *takeaway*, not the type: `aria-label="Skills by category: writing 14, data 9, ops 6, other 3."` Set `aria-hidden="true"` on all internal SVG nodes.
2. **A real `<table>` fallback** in a `<details>` beneath every chart — `<summary>View data as a table</summary>`. This is the only universally reliable pattern and it doubles as agent-readable content.
3. **Never color alone (1.4.1).** Add direct labels, patterns (`<pattern>` fills), and varied dash arrays/markers.
4. **3:1 contrast (1.4.11)** for every series stroke and every meaningful boundary against the plot background; adjacent series need 3:1 *from each other* too.
5. **Forced colors:** `forced-color-adjust: none` on the chart root and a `@media (forced-colors: active)` branch that switches to `CanvasText` strokes differentiated purely by dash pattern + direct label.
6. **Reduced motion:** no entrance animations, no auto-play transitions.
7. **Interactive tooltips** must be keyboard reachable (focusable data points with roving tabindex) *and* dismissable with `Esc` (1.4.13).
8. **[inferred]** Given the design brief, prefer static server-rendered SVG over a canvas charting lib — canvas has no accessibility tree at all and forces you into the table fallback as the *only* alternative.

# PART 2 — Keyboard shortcut map

## 2.1 The constraint that drives the design: WCAG 2.1.4

**SC 2.1.4 Character Key Shortcuts (Level A)** — **[verified]** verbatim from W3C: if a shortcut uses only letter/punctuation/number/symbol characters, then **at least one** of: *Turn off* (mechanism to disable), *Remap* (mechanism to add a non-printable modifier), or *Active only on focus* (only active when the relevant component has focus).

**Our compliance stance — implement all three:**

1. **Active only on focus (primary):** single-character shortcuts are bound to the **reader region**, not `document`. The handler lives on `<main>` (or the `<article id="book">`) with `onKeyDown`, and only fires when `document.activeElement` is inside that region. Because `<main tabIndex={-1}>` receives focus after a skip link or chapter change, the shortcuts "just work" for keyboard users without being global.
2. **Turn off:** a `Keyboard shortcuts` switch in the controls panel, default **on**, persisted in `localStorage` under `sb:shortcuts:enabled`.
3. **Remap:** a `Customize…` sub-panel writing to `sb:shortcuts:keymap` (JSON `{ actionId: string[] }`), with a "Require a modifier for all shortcuts" one-click preset that rewrites every single-char binding to `Alt+<key>`.

**Additional guards in the handler (all required):**

- Ignore when `event.target` matches `input, textarea, select, [contenteditable=""], [contenteditable="true"]`.
- Ignore when `event.isComposing` (IME) or `event.keyCode === 229`.
- Ignore when `ctrlKey || metaKey || altKey` is set for single-char bindings (so `Cmd+D` bookmarks normally).
- Use `event.code` for physical keys (`ArrowRight`, `Space`, `BracketRight`) and `event.key` for characters, so non-QWERTY layouts aren't broken.
- Never `preventDefault()` unless the binding actually matched.

## 2.2 Screen-reader collision analysis

NVDA and JAWS in **browse/virtual mode** intercept single letters before the page ever sees them: `h` (heading), `1`–`6` (heading level), `k` (link), `b` (button), `l` (list), `i` (list item), `t` (table), `f` (form field), `e` (edit box), `d` (landmark, NVDA), `g` (graphic), `c` (combo box), `x` (checkbox), `r` (radio), `q` (blockquote), `n` (skip past links), `s` (separator), `,`/`.` are largely free. VoiceOver uses `VO`(Ctrl+Opt)+key, so it does not collide with bare letters.

**Consequence, and the rule that follows:** an SR user in browse mode will *not* be able to trigger our letter shortcuts, and that is fine — they navigate by headings and landmarks, which we provide. **Therefore no function may be shortcut-only.** Every action in the table below has a visible, labeled, tabbable control. We also do not attempt to "fix" this with `role="application"` — that would break browse mode and is a net accessibility loss.

## 2.3 Browser reservations avoided

Reserved and **not used**: `Ctrl/Cmd + D N P S T W R O F L H J U I 1-9 +/-/0`, `Alt/Cmd + ←/→` (history), `Cmd + [ / ]` (Safari history), `F1`–`F12`, `Ctrl/Cmd+Shift+ N P T I J C`, `Space` while a button has focus (activates it — see note below).

Two deliberate, industry-standard exceptions:
- **`Ctrl/Cmd+K`** — focuses the browser address bar in Chrome and Firefox by default, but web content *can* `preventDefault()` it in both, and every modern app (GitHub, Linear, Vercel, Notion) binds it. We bind it **and** provide `/` as the modifier-free equivalent. **[inferred]**
- **`Space` / `Shift+Space`** — the browser default is page-scroll, which *is* the page-turn semantic in continuous mode, so we only `preventDefault()` in paginated mode, and only when focus is not on a button/link/checkbox (where Space activates).

- Comma for settings mirrors the universal `Cmd+,` preferences idiom.
- `?` for help is the de facto standard (GitHub, Gmail, Slack, Linear).

```tsx
  scopeRef, enabled, keymap, onAction, global = new Set(['ui.search', 'ui.help']),
}: {
  scopeRef: React.RefObject<HTMLElement | null>
  enabled: boolean
  keymap: Record<string, string[]>
  onAction: (id: string, e: KeyboardEvent) => void
  global?: Set<string>
}) {
  const chord = useRef<{ key: string; at: number } | null>(null)

  useEffect(() => {
    if (!enabled) return
    const lookup = buildLookup(keymap) // "Shift+ArrowRight" -> actionId, "g b" -> actionId

    function onKeyDown(e: KeyboardEvent) {
      if (e.isComposing || e.keyCode === 229) return
      const target = e.target as HTMLElement | null
      if (target?.closest?.(EDITABLE)) return

      const combo = serialize(e) // normalizes Meta/Ctrl -> "Mod", preserves Shift/Alt
      // two-key chord
      if (chord.current && Date.now() - chord.current.at < 1500) {
        const id = lookup.get(`${chord.current.key} ${combo}`)
        chord.current = null
        if (id) { e.preventDefault(); onAction(id, e); return }
      }
      if (combo === 'g') { chord.current = { key: 'g', at: Date.now() }; return }

      const id = lookup.get(combo)
      if (!id) return

      // 2.1.4: single-char bindings are active only when focus is inside the reader
      const isSingleChar = combo.length === 1
      const inScope = !!scopeRef.current && !!target && scopeRef.current.contains(target)
      if (isSingleChar && !global.has(id) && !inScope) return

      e.preventDefault()
      onAction(id, e)
    }

    document.addEventListener('keydown', onKeyDown)
    return () => document.removeEventListener('keydown', onKeyDown)
  }, [enabled, keymap, onAction, scopeRef, global])
}
```

## 2.6 The shortcuts help dialog

Requirements:

- Opens on `?`, **and** from a visible `Keyboard shortcuts` item in the controls panel, **and** from a footer link. Discoverability is a 3.3.5-style courtesy but mostly a product requirement — undiscoverable shortcuts are decoration.
- Rendered as a Base UI `Dialog` with `modal={true}`, a real `Dialog.Title` ("Keyboard shortcuts"), and a `Dialog.Close` inside the popup.
- Content is a set of `<dl>` groups (Reading, Navigation, Actions, Display) — `<dt>` is the action, `<dd>` holds `<kbd>` elements.
- **Reflects the live keymap**, including user remaps, and shows platform-correct glyphs (`⌘` on Apple, `Ctrl` elsewhere) — detect via `navigator.userAgentData?.platform ?? navigator.platform`.
- Each `<kbd>` group gets an SR-friendly reading: `<kbd aria-label="Shift plus Slash">⇧ /</kbd>` — otherwise VoiceOver reads "shift slash" as punctuation soup.
- Includes, in the dialog itself: the **Enable keyboard shortcuts** switch and a **Customize…** link, satisfying 2.1.4's "turn off"/"remap" discoverability.
- Also expose the whole map to agents at `/api/v1/shortcuts` (see §3.5) and in `llms.txt` — an agent driving the reader needs it.

**llms.txt spec [verified] from llmstxt.org** — the file is markdown at `/llms.txt` with, in order: optional BOM; **an H1 (the only required element)**; an optional blockquote summary; zero or more prose sections (no headings); zero or more `##`-delimited "file list" sections, each a markdown list of `[name](url): notes`. ## 4.2 Decision: `.md` suffix is canonical; `Accept` negotiation is a bonus

**Recommendation: implement `/{owner}/{repo}.md` as the canonical markdown URL, and *also* honor `Accept: text/markdown` on the HTML routes as a convenience. Reject `/{owner}/{repo}/md`.**

Justification:

1. **`/{owner}/{repo}/md` collides with our own route space.** Chapters live at `/{owner}/{repo}/{skill}`. A repo containing a skill literally named `md` (or `json`, or `raw`) would be shadowed. Path-segment suffixes are a design smell for any app with user-controlled trailing segments. Disqualifying on its own.
2. **A distinct URL is a distinct cache key.** `Accept`-based negotiation forces `Vary: Accept` on the HTML route, which fragments every CDN edge cache by a header that browsers send with enormous variability (`text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,...`). Anthropic sidesteps this by setting `cache-control: private, no-store` on the negotiated route — i.e. they gave up caching to make it work (**[verified]**). Vercel's `.md` route, by contrast, is `public, max-age=3600` (**[verified]**). We want the cacheable one as canonical.
3. **`.md` URLs are linkable, pasteable, and quotable.** They go in `llms.txt`, in `<link rel="alternate">`, in READMEs, in agent transcripts. A header-negotiated URL cannot be shared as "the markdown one."
4. **Many crawlers can't or won't set `Accept`.** GPTBot, ClaudeBot, and CCBot fetch with generic accept headers. A URL works for everyone.
5. **It's what the ecosystem converged on** — Anthropic, Vercel, Mintlify all serve `.md` (**[verified]** all three).

**Also honor `Accept: text/markdown`** because it costs ~15 lines in `proxy.ts`, it's what a well-behaved agent will try first, and Mintlify/Anthropic/Vercel all support it. Set `Vary: Accept` + `Cache-Control: public, s-maxage=600, stale-while-revalidate=86400` on that path and accept the modest cache fragmentation, since the canonical `.md` URL carries the traffic.

**Cross-link the two directions:**
- On HTML: `<link rel="alternate" type="text/markdown" href="/{owner}/{repo}.md">` plus the `Link` response header.
- On markdown: `Link: <https://…/{owner}/{repo}>; rel="canonical"` (exactly what Vercel does — **[verified]**).

### Implementation: `src/proxy.ts` (Next 16 — **not** `middleware.ts`)

```ts
// src/proxy.ts
import { NextResponse, type NextRequest } from 'next/server'

const DISCOVERY_LINK = [
  '</llms.txt>; rel="llms-txt"',
  '</llms-full.txt>; rel="llms-full-txt"',
  '</.well-known/agent-skills/index.json>; rel="agent-skills"',
  '</.well-known/api-catalog>; rel="api-catalog"',
  '</api/v1/openapi.json>; rel="service-desc"',
].join(', ')

/** q-value aware: markdown only wins if it outranks html */
function prefersMarkdown(accept: string): boolean {
  if (!accept) return false
  const q = (type: string) => {
    const m = new RegExp(`(?:^|,)\\s*${type.replace('/', '\\/').replace('*', '\\*')}\\s*(?:;\\s*q=([0-9.]+))?`, 'i').exec(accept)
    return m ? (m[1] ? parseFloat(m[1]) : 1) : -1
  }
  const md = Math.max(q('text/markdown'), q('text/x-markdown'))
  const html = Math.max(q('text/html'), q('application/xhtml\\+xml'))
  return md > 0 && md > html
}

/** /owner/repo and /owner/repo/skill — 1 or 2 segments, no dots in owner */
const READER_ROUTE = /^\/[A-Za-z0-9](?:[A-Za-z0-9-]{0,38})\/[A-Za-z0-9._-]{1,100}(?:\/[A-Za-z0-9._-]{1,100})?$/

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl

  // 1. Canonical: .md suffix -> markdown route handler
  if (pathname.endsWith('.md')) {
    const bare = pathname.slice(0, -3)
    if (READER_ROUTE.test(bare)) {
      const url = request.nextUrl.clone()
      url.pathname = `/api/md${bare}`
      const res = NextResponse.rewrite(url)
      res.headers.set('Link', `<${request.nextUrl.origin}${bare}>; rel="canonical", ${DISCOVERY_LINK}`)
      return res
    }
  }

  // 2. Convenience: Accept negotiation on the HTML reader routes
  if (READER_ROUTE.test(pathname) && prefersMarkdown(request.headers.get('accept') ?? '')) {
    const url = request.nextUrl.clone()
    url.pathname = `/api/md${pathname}`
    const res = NextResponse.rewrite(url)
    res.headers.set('Vary', 'Accept')
    res.headers.set('Link', `<${request.nextUrl.origin}${pathname}>; rel="canonical", ${DISCOVERY_LINK}`)
    return res
  }

  // 3. Advertise discovery on every HTML response
  const res = NextResponse.next()
  res.headers.set('Link', DISCOVERY_LINK)
  res.headers.set('X-Llms-Txt', '/llms.txt')
  return res
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico|.*\\.(?:png|jpg|jpeg|svg|webp|ico|woff2?)$).*)'],
}
```

> Why a rewrite is unavoidable: `app/[owner]/[repo]/page.tsx` matches `/anthropics/skills.md` with `repo === "skills.md"` — dynamic segments happily contain dots. Without the proxy rewrite, the HTML page would win. **[verified]** by the dynamic-routes semantics in the bundled Next docs.

```ts
// src/app/api/v1/books/[owner]/[repo]/route.ts
import { getBook } from '@/lib/books'

export const revalidate = 3600

const JSON_HEADERS = {
  'content-type': 'application/json; charset=utf-8',
  'access-control-allow-origin': '*',
  'access-control-allow-methods': 'GET, HEAD, OPTIONS',
  'cache-control': 'public, max-age=0, s-maxage=3600, stale-while-revalidate=86400',
  'x-robots-tag': 'all',
}

export async function GET(_req: Request, ctx: RouteContext<'/api/v1/books/[owner]/[repo]'>) {
  const { owner, repo } = await ctx.params
  const book = await getBook(owner, repo)
  if (!book) {
    return Response.json(
      { error: { code: 'not_found', message: `No indexed book for ${owner}/${repo}.`,
                 hint: 'Visit https://githubskills.book/{owner}/{repo} to trigger indexing.' } },
      { status: 404, headers: JSON_HEADERS })
  }
  return Response.json(book, { headers: JSON_HEADERS })
}

export async function OPTIONS() {
  return new Response(null, { status: 204, headers: JSON_HEADERS })
}
```

```ts
// src/app/[owner]/[repo]/.well-known/agent-skills/index.json/route.ts
import { createHash } from 'node:crypto'
import { getBook, getSkillRaw } from '@/lib/books'

export const revalidate = 3600

export async function GET(
  _req: Request,
  ctx: RouteContext<'/[owner]/[repo]/.well-known/agent-skills/index.json'>,
) {
  const { owner, repo } = await ctx.params
  const book = await getBook(owner, repo)
  if (!book) return Response.json({ error: { code: 'not_found', message: 'Unknown book' } }, { status: 404 })

  const base = 'https://githubskills.book'
  const skills = await Promise.all(book.chapters.map(async (c) => {
    const raw = await getSkillRaw(owner, repo, c.name)
    return {
      name: c.name,
      type: 'skill-md' as const,
      description: c.description,
      url: `${base}/${owner}/${repo}/${c.name}.md`,
      digest: `sha256:${createHash('sha256').update(raw).digest('hex')}`,
    }
  }))

  return Response.json(
    { $schema: 'https://schemas.agentskills.io/discovery/0.2.0/schema.json', skills },
    { headers: {
        'cache-control': 'public, max-age=0, s-maxage=3600, stale-while-revalidate=86400',
        'access-control-allow-origin': '*',
      } },
  )
}
```

## 4.9 `robots.txt` — permissive by design

Static file is fine and avoids a runtime dependency, but `app/robots.ts` gives typed generation (**[verified]** `.../01-metadata/robots.md`).

```ts
// src/app/robots.ts
import type { MetadataRoute } from 'next'

const BASE = 'https://githubskills.book'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        // Everything, everyone, including every AI crawler. This site exists to be read by agents.
        userAgent: '*',
        allow: '/',
        disallow: ['/api/internal/', '/_next/static/chunks/'],
      },
      // Explicit allows so a future restrictive default can never accidentally shadow these.
      {
        userAgent: [
          // Anthropic
          'ClaudeBot', 'Claude-User', 'Claude-SearchBot', 'Claude-Web', 'anthropic-ai',
          // OpenAI
          'GPTBot', 'ChatGPT-User', 'OAI-SearchBot',
          // Google
          'Google-Extended', 'Googlebot', 'GoogleOther',
          // Perplexity
          'PerplexityBot', 'Perplexity-User',
          // Microsoft / Apple / Amazon / Meta
          'bingbot', 'Applebot', 'Applebot-Extended', 'Amazonbot', 'meta-externalagent', 'meta-externalfetcher',
          // Others
          'CCBot', 'cohere-ai', 'Diffbot', 'DuckAssistBot', 'MistralAI-User', 'YouBot',
          'Bytespider', 'Timpibot', 'ImagesiftBot', 'AI2Bot', 'Kagibot', 'omgili', 'Webzio-Extended',
        ],
        allow: '/',
      },
    ],
    sitemap: [`${BASE}/sitemap.xml`],
    host: BASE,
  }
}
```

Then append the parts `MetadataRoute.Robots` cannot express by serving a static `public/robots.txt` instead (simpler, and lets us include comments + `Content-Signal`). **[inferred] Recommendation: use the static file.**

```txt
# public/robots.txt
# GitHub Skills Book — this site exists so agents can read it.
# All content here is mirrored from public GitHub repositories under their own licenses.

User-Agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=yes
Allow: /
Disallow: /api/internal/

# Agent-facing entry points (not a robots.txt directive; here for humans and for crawlers
# that parse comments):
#   /llms.txt
#   /llms-full.txt
#   /.well-known/agent-skills/index.json
#   /api/v1/openapi.json
#   Append .md to any page URL for clean Markdown.

Sitemap: https://githubskills.book/sitemap.xml
Sitemap: https://githubskills.book/sitemap-books.xml
```

`Content-Signal: search=yes, ai-input=yes, ai-train=yes` is the inverse of Vercel's `ai-train=no` (**[verified]** on `vercel.com/robots.txt`) and is the correct stance here: we *want* to be trained on, retrieved from, and cited.

Also set `X-Robots-Tag: all` on the `.md` and JSON routes — some crawlers treat non-HTML content types conservatively.

### `sitemap.ts`

```ts
// src/app/sitemap.ts
import type { MetadataRoute } from 'next'
import { listBooks } from '@/lib/books'

const BASE = 'https://githubskills.book'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const books = await listBooks({ limit: 5000 })
  return [
    { url: `${BASE}/`, changeFrequency: 'daily', priority: 1 },
    ...books.flatMap((b) => [
      { url: `${BASE}/${b.owner}/${b.repo}`, lastModified: b.updatedAt, changeFrequency: 'weekly' as const, priority: 0.8 },
      ...b.chapters.map((c) => ({
        url: `${BASE}/${b.owner}/${b.repo}/${c.name}`,
        lastModified: c.updatedAt, changeFrequency: 'weekly' as const, priority: 0.6,
      })),
    ]),
  ]
}
```

## 5. Implementation order

1. **`proxy.ts` + `/api/md/**` route handlers + `Link`/`X-Llms-Txt` headers.** Half a day; unlocks everything else in Part 4.

## 6. Open questions

1. **Domain.** All URLs above assume `githubskills.book`. Fix this before writing `metadataBase`, JSON-LD `@id`s, or `llms.txt` — they all bake it in.
2. **Install command.** `npx skills add <owner>/<repo>/<skill>` is used throughout as the canonical install string (it matches the `npx skills add supabase/agent-skills` form seen in the wild). Confirm the actual CLI before it ships in OG images, `llms.txt`, and the copy button.
3. **`schemas.agentskills.io/discovery/0.2.0/schema.json` returned an empty body over plain curl** during research — the `$schema` URL is taken verbatim from Mintlify's live manifest, but I could not fetch and validate the schema document itself. Validate before relying on field names beyond `name`/`type`/`description`/`url`/`digest`.
4. **Third-party a11y violations in CI.** Skill markdown we don't control *will* produce axe violations (missing alt, bad heading order pre-repair, low-contrast inline HTML). Decision needed: fail CI on a fixture repo, or scan only our chrome in CI and surface content violations in the per-book "Accessibility report" UI. **[inferred] Recommendation:** CI gates on our chrome + a curated clean fixture; content violations become product surface, not build failures.
